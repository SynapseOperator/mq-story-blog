# MQ 设计核查与实施裁决（Codex 必读）

> 基于产品负责人多轮明确确认；**本文件不替换原 PRD，也不偷偷补充未经确认的产品功能**。优先使用 PRD v1.1 正文与验收清单进行项目范围控制。

## 1. 本次交接已经核对的需求

| 决定 | 必须遵守的解释 |
|---|---|
| 项目类型 | 老师要求**个人博客**，允许 GitHub 替换华为工具链；不能按完整 X 社交平台进行需求扩展。MQ 共用主页优先，M/Q 正式个人主页以后设计。 |
| 首页与场景 | 默认 MQ 星空青草山坡，情侣坐在山坡上、篝火；无萤火虫；中央上方 MQ 艺术 Logo。 |
| 首页导航 | 左侧 MQ/M/Q 固定于**各分区初始页**；M/Q 首版为带返回入口的“建设中”页。阅读信纸时导航与右上角普通登录入口都**隐藏**。 |
| 故事入口 | 只有**明亮故事星**和**篝火**作为场景故事入口；背景微小星尘纯装饰。每颗明亮星对应一篇公开故事；篝火对应固定的《我们在一起的故事》。 |
| 星位 | A+B 融合式持续生长，但首版**预设可选星位**；管理员后台选空位。**自由拖拽**是未来按需功能，不提前开发。 |
| 羽毛信 | 参考 E 的真实旧信纸 + B 的温柔情书；位于画面中央，背景保留变暗，**自上向下平滑展开**、轻微纸张舒展感，非木轴卷轴；同一信纸上连续展示文章、图片、点赞和“留言”。 |
| 环境动效 | 轻微鼠标视差；星星细微闪烁、青草轻摆、篝火自然燃烧；篝火悬停时**火焰与暖光明显增强**，不是把整堆木柴放大。 |
| 评论 | 游客可匿名留言；所有留言（含已登录用户）需管理员审核后才公开；失败时保留输入，防重复提交。 |
| 点赞与登录 | 用户名+密码普通账号；**登录后才可点赞和取消**。游客读信点击点赞时，在信纸上方出现小型登录弹窗，关闭/登录成功后回到原文章同滚动位置。 |
| 后台 | 唯一管理员账号，由两位维护者共用；公开注册永远不能获得管理员权限；服务端授权必须有效。 |
| 分享链接 | 每篇已公开故事有 `/stories/:slug` 形式的独立链接；直达后仍显示 MQ 星空暗化背景 + 居中羽毛信；未发布或下架内容不得泄露。 |
| 故事目录 | **移动端**采用可收起回忆目录作为辅助文章入口；入口**具体位置、外观仍未确定**，需后续视觉原型评审。 |
| 异常与质量 | 用户已确认：友好错误、重试、移动端、动效降级、安全权限、内容隐私、数据持久化及备份恢复等作为默认原则。 |

## 2. 发现的资料差异：以文字要求为准

1. **视觉概念图不是逐像素需求**：图中的 Logo 左上角，与最终确定的“中央上方”不同；湖泊、村镇、灯具、装饰花朵不是必需元素。
2. **概念图中的文章、评论、日期与点赞数字是演示内容**，不能直接写成真实产品或公开真实故事。图包含模拟文本，也不意味着最终页面可以直接使用单张扁平背景图代替分层交互。
3. **旧草图里的导航**仅在 MQ/M/Q 各自初始主页展示并保持固定。阅读层并不是能够点击导航继续切换的页面。
4. **首版原型≠完整博客**。原型可用标注清楚的演示故事，但未搭建持久数据库、权限、审核，不得声称完整功能已完成。
5. **管理员账号只有一个**，共用账号无法可靠区分两位成员的个人后台操作；课程中的 GitHub 开发贡献仍分别使用个人 GitHub 账号记录，不能因为后台共用账号而共用 GitHub 账号。

## 3. 仍须在原型或技术评审中决定，不得自作主张冻结

- 回忆目录**具体摆放位置和外观**，以及是否在桌面端开放。
- 信纸最终宽度、高度、纸张纹理资源、中文字型、动画时长和暗化强度（PRD 中数字仅为原型试验起点）。
- 手机端星位分布、候选星位数量、位满扩展策略、背景艺术素材的最终制作方式。
- 账号输入长度、留言长度、密码策略、限流阈值、备份方案参数等后续技术约束。
- **部署方式尚未定版**：不能因为教师允许 Github 替代华为工具，就假设任何托管平台都可自动抵扣“主机配置”验收。

## 4. 实施纪律

- 第一轮只建立可复用的 Next.js/TypeScript 工程基座、项目文档和基础 GitHub 流程。**不要开发 MQ 完整主页、伪造数据库或一次完成全部业务。**
- 后续先做高保真交互原型，采用分层设计、真实 UI 元素和演示数据；确认画面以后再添加用户认证、数据库、审核与发布后台。
- 不向 GitHub 上传 `LOCAL_ONLY_REFERENCE` 文件，不包含用户原始手绘稿和教师原始课程文件。设计参考图在 PROJECT_IMPORT 下允许进入**默认私有**仓库，但若未来要改公开仓库需重新审查内容和许可。
- 不设置或打印管理员真实密码；首轮不创建真实管理员业务账号，不采购云服务，不做正式部署。

# MQ 项目执行路线与第一批实际工作项（草案）

> 第一轮授权范围是**项目初始化（Stage 0）**，完成后停下等待用户确认下一个开发 PR；下面的阶段拆解不能理解为一次性启动全量开发。

## Phase 0｜建立可用工程基座 + GitHub 仓库

- 在 Codex 当前工程工作区中创建独立 `mq-story-blog`，检查是否有同名仓库/目录，避免嵌套 Git 意外跟踪。
- 阅读本包 PRD v1.1 与验收清单；复制 PROJECT_IMPORT 下正式资料到新仓库的 `docs/`。
- 新建 Next.js + TypeScript + Tailwind CSS + ESLint 的最小工程（以环境兼容与当前成熟版本为准，不盲目升级）。初始页面可展示低调、标有“工程占位”的运行页面，**不得假装正式的 MQ 星空**。
- 创建 README、项目级 AGENTS.md（仅必要约束）、.gitignore、PR/Issue 模板（轻量）、基础 CI：lint/typecheck/build，根据真实安装情况可加可验证的小测试。
- 用用户已授权的私有 GitHub 仓库记录真实初始化提交。配置所支持的基础 GitHub Issues、标签和迭代；若 Projects API 不可用，明确列为待办，而非宣称已完成。
- 收尾回报：本地路径、私有仓库地址、真实构建/CI 记录、Issues 链接、未决项。

## Phase 1｜视觉交互原型（验收清单 UX-01~UX-24）

**先后建议（独立小 PR）：**

1. `prototype: scene layout`：MQ 初始星空、山坡青草、情侣、篝火、Logo、固定导航 + M/Q 建设中占位。确认场景分层和移动端占位策略，不用一张整图充当最终交互网页。
2. `prototype: ambient motions`：故事星/背景星尘层次、轻微视差、草地轻摆、篝火燃烧/悬停变旺，设置减弱动效；真实浏览器验证。
3. `prototype: feather letter`：故事星/篝火点开同一信纸阅读层、向下展开、暗化背景、阅读层内滚动、关闭/未提交留言确认；含移动端可收起目录**但未确认其最终位置**。

只使用清楚标注的演示文章。原型评审记录实际完成与未通过项，不提前宣称真实认证、数据库、点赞和评论审核已实现。

## Phase 2｜真实博客核心功能

服务端认证与权限、唯一共享管理员账号、故事增删改与发布、预设星位、点赞/取消、匿名/登录留言和管理员审核、稳定故事分享 URL、数据库和备份，按用户故事小步开发并补真实测试。先验收权限、发布和公开阅读三条主链路。

## Phase 3｜部署与课程验收

确认主机/等价环境的老师验收口径后，选择部署技术，建立 CI/CD、发布与恢复演练，形成可核查的项目管理、代码、测试、部署及总结反思证据。

# 小型 VPS 的备份：把数据库和图片一起恢复

MQ Story 的正文和图片不是同一份存储：PostgreSQL 保存故事、修订和媒体引用，私有媒体卷保存处理后的图片。只保存数据库 dump，可能恢复出一篇引用了丢失图片的故事；只复制图片，也不能重建当时的发布状态和权限。

项目采用 PostgreSQL 原生 `pg_dump`、Restic 加密仓库和一份图文清单。这里介绍三者如何连起来，实际操作参数与失败处理见[备份恢复手册](../engineering/PRODUCTION_BACKUP.md)。

## 先选择可以解释清楚的一致性方式

这个规模的博客可以接受短暂维护窗口，因此没有引入持续增量归档或跨存储事务：先停止应用及维护写入，排空写连接，再复制数据库和图片。

四个写入身份设为 `NOLOGIN` 后还要确认连接已排空，因为禁止新登录不会结束已有连接。备份、恢复和密钥轮换共用维护锁，避免受控操作互相插入。备份读取媒体清单和 `pg_dump` 使用同一个 PostgreSQL 导出快照；遇到尚在上传或删除中的媒体则退出，先由既有媒体恢复流程处理。

取舍很直接：实现和故障处理更容易核对，但停写覆盖远端上传和校验，数据量增长会延长窗口。它不是零停机备份，也不能阻止 root 或数据库高权限人员在窗口里绕过工具修改文件。

## “上传了快照”还不够

[`backupDeployment`](../../scripts/production/backup.mjs) 完成以下步骤后才写成功回执：

1. 核对目标、备份身份、迁移记录和工作区余量。
2. 复制 READY 媒体的展示图与缩略图，逐一核对大小和 SHA-256；生成同一快照下的 custom-format 数据库 dump。
3. 写入数据库、媒体清单、部署 ID、源码版本和迁移数量等恢复元信息，再检查这份明文载荷。
4. 调用 Restic 加密上传，执行 `check --read-data`，将本次**精确快照 ID**重新提取到新目录并核验。
5. 只清理本次成功操作创建的明文子目录，排他写入成功回执。

非零退出、部分成功或校验失败都不会生成新成功回执。监控读取回执里的目标、仓库 ID、快照和时间，不能把上一次成功文件当作本次成功。窗口协调器还要单独确认应用恢复服务；备份成功本身不证明网站已经恢复可用。

## 恢复到新地方，才能保留退路

[`restoreDeployment`](../../scripts/production/restore.mjs) 要求新 deployment ID、空数据库对象和空媒体根。它用迁移身份导入备份，不带 `--clean` 覆盖原库，也不以 superuser 执行导入内容。

恢复时核对 dump 和图片摘要，再与恢复后的媒体记录比较；清除全部 Session 和旧业务签名密钥。管理员授权与故事保留，但旧登录和旧发布/审核证明不能复活。接下来需要配置新目标的权限和秘密，运行权限审计，并在隔离入口验证应用。恢复完成不会自动开放公网。

一个有意义的演练应检查：正文与图片能对应、已发布与草稿的访问边界正确、普通用户不能进入后台、旧 Cookie 失效，以及服务重建后的数据仍在。仅看到 `pg_restore` 退出 0 不足以回答这些问题。

## 小磁盘与异地存储的实际约束

备份期间会同时存在 dump、媒体副本和校验提取目录。当前工具按数据库估算大小与媒体字节数的三倍，再加固定余量做空间准入；它不是磁盘硬配额，其他进程仍可能占满主机。不要让构建缓存和长期明文备份占掉恢复所需空间。

Restic 密码与 S3 凭据分开管理：前者用于解密，后者决定谁能访问远端对象。应用容器不需要这两项秘密。仓库 ID 固定在配置中，错误密码或前缀不能触发自动新建仓库；测试与生产使用不同前缀和身份。密码须有独立恢复副本，只在同一 VPS 上多放一份文件不能替代异地备份。

当前方案保留每日备份与完整数据校验，保留策略只做 `7 daily / 8 weekly` 的 dry-run。完整 `check --read-data` 会读取仓库数据，精确快照恢复还会产生额外下载；估算费用时要同时看存储、请求和出网，不能只看每 GB 存储单价。按实际账单和演练耗时调整方案，而不是静默减少校验。

## 从哪里读代码、怎样复现

- [backup.mjs](../../scripts/production/backup.mjs)：一致性、载荷校验和成功回执。
- [backup-tools.mjs](../../scripts/production/backup-tools.mjs)：Restic、S3、秘密文件和空间合同。
- [restore.mjs](../../scripts/production/restore.mjs)：新目标恢复与 Session 失效。
- [backup-window.mjs](../../scripts/production/backup-window.mjs)：停止写入、备份和恢复服务的顺序。

`npm run test:production:operations` 用合成数据验证备份与恢复，构建及运行前提见[生产基础](../engineering/PRODUCTION_FOUNDATION.md)和[开发指南](../DEVELOPMENT.md)。它与真实供应商的 IAM、带宽、费用及定时任务验收分开；工具提供了这些能力，不代表新安装的实例已经启用了它们。
